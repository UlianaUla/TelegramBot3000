## Ручной расчёт за один период

Входные данные: одна книга 640 ₽; её сохранённая себестоимость 320 ₽; операционный расход «Реклама» 100 ₽. Заказ и все подтверждения относятся к выбранному периоду.

1. Pending: поступления 0, возвраты 0, расходы 0 → поток 0 ₽, учебный результат 0 ₽.
2. Оплата подтверждена: 640 − 0 − 0 = **640 ₽** потока; 640 − 0 − 320 + 0 − 0 = **320 ₽** результата.
3. Расход 100 ₽: 640 − 0 − 100 = **540 ₽** потока; 640 − 0 − 320 + 0 − 100 = **220 ₽** результата.
4. Возврат только запрошен: прежние **540 ₽ / 220 ₽**.
5. Полный возврат подтверждён: 640 − 640 − 100 = **−100 ₽** потока; 640 − 640 − 320 + 320 − 100 = **−100 ₽** результата.

Эти результаты совпали с `test_payment_refund_lifecycle_and_exact_formulas`.

Второй пример без расходов: сентябрьская оплата 640 ₽/себестоимость 320 ₽, октябрьский полный возврат → сентябрь **+640/+320 ₽**, октябрь **−640/−320 ₽**. Проверка `test_other_period_uses_confirmation_not_creation` совпала. Поэтому текущий период может быть отрицательным из-за возврата старой продажи.
