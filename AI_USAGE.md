# Использование AI-помощника

## Основной запрос

В ходе работы использовался запрос на продолжение существующего книжного Telegram-магазина: добавить общую базу себестоимости, платежей и финансовых операций, два финансовых показателя за период, Mini App менеджера с проверкой Telegram initData, расходы, полные возвраты, уведомления и /summary. Изначально был реализован учебный имитатор для проверки состояний; затем по уточнению владельца оставлена тестовая ссылка API ЮKassa.

Это краткое изложение реального запроса из переписки, а не утверждение о дословном тексте. Для сдачи при необходимости приложите оригинал без токенов и ключей.

## Примеры уточнений и исправлений

1. «Убери мне имитатор, мне нужна оплата тестовая через юкассу … как мне настроить юкассу для тестовой оплаты?» — учебные кнопки отключены, выбран тестовый магазин, добавлена инструкция получения ключа. Номер магазина в публикуемом примере опущен.
2. «А где mini app?» — добавлена заметная кнопка кабинета, запускатель HTTPS и инструкция открытия из Telegram. Разобрано отличие готовой страницы от её публичного размещения.
3. «Проверь, всё ли сделано по заданию…» — выполнены тесты и HTTPS-проверка, добавлены проверки уведомлений и /summary, актуализирован README, составлен CHECK_REPORT.md с незавершёнными пунктами сдачи.

## Что выполнено автоматически

AI редактировал исходники и документацию, запускал автоматические тесты, проверял доступность публичной страницы и отказ API без авторизации. Программные тесты использовали вымышленные ID и подставленные ответы провайдера. Их нельзя описывать как самостоятельную ручную демонстрацию пользователя.

## Этап склада (24 октября 2026)

Основной запрос: «Сделай всё, что написано в документе store-stock.md» — продолжить прежний магазин, добавить атомарный резерв, складские движения, позднюю оплату, устойчивые возвраты и HTTP-приёмку.

Уточнения, реализованные при проверке:

- Резерв всего состава и сохранённый отказ используют один ключ запроса; другую корзину с прежним ключом сервер отвергает.
- Старые succeeded/pending/canceled не могут откатить успешный платёж или завершённый возврат.
- Фоновое освобождение отделено от долгих вызовов провайдера, чтобы сетевая задержка не блокировала срок резерва.

Сбой Windows и его исправление записаны в STOCK_DEBUG_LOG.md, фактические команды и результаты — STOCK_REPORT.md. Серверная приёмка запускает два независимых процесса и отдельные SQLite-файлы. Не приписывайте себе эти автоматические действия как ручную проверку: самостоятельно дополните раздел личного вклада после демонстрации.
