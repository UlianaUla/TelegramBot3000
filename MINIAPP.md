# Открытие Mini App из Telegram на Windows

Mini App уже находится в `bot/static/index.html`, API и проверка подписи — в `bot/web.py`. Страница и сервер запускаются вместе с магазином. Доступ к финансовым данным получает только менеджер из локального `.env`.

## Обычный запуск для демонстрации

1. Остановите прежний запуск бота клавишами Ctrl+C.
2. В папке проекта дважды щёлкните `start-miniapp.cmd` или в cmd выполните:

```bat
cd /d "C:\Users\User\Desktop\Telegram bot"
start-miniapp.cmd
```

3. При первом запуске загружается cloudflared из официального репозитория Cloudflare. Нужен интернет. Если менеджер ещё не настроен, программа попросит ваш числовой Telegram ID, полученный командой `/id` в боте. Если ID уже сохранён, вопроса не будет.
4. Запускатель создаёт HTTPS-туннель к локальному порту 8080, сохраняет выданный URL в `.env` и запускает бот. В окне появится строка `Mini App: https://...trycloudflare.com`. Секреты туда не выводятся.
5. Оставьте окно открытым. В своём боте в Telegram отправьте `/start`, нажмите **«Финансы · Mini App»**, затем **«Открыть Mini App»**. Это кнопка Telegram `web_app`, приложение открывается внутри Telegram.

Для виртуального окружения вместо cmd-запускателя можно выполнить `.venv\Scripts\python.exe -m bot.launch`, предварительно установив в это окружение `requirements.txt`. Команда `python -m bot` запускает HTTP-сервер только локально; для доступа из Telegram нужен работающий туннель или собственный HTTPS-сервер.

Quick Tunnel — временный адрес для учебной демонстрации, не постоянный хостинг. После нового запуска адрес меняется: снова отправьте `/finance` для получения новой кнопки. Старые кнопки в истории чата останутся со старым URL. Остановка окна или компьютера выключает приложение. Для постоянного размещения нужен сервер с постоянным HTTPS-адресом; в таком случае укажите его в `MINI_APP_URL` и запускайте `python -m bot` без Quick Tunnel.

Если Cloudflare недоступен из вашей сети, запускатель покажет ошибку; используйте доступный HTTPS-прокси или собственный сервер. Произвольный адрес в `.env` без работающего сервера проблему не решит. Если порт занят, остановите предыдущую программу, не запускайте второй polling-процесс бота.

## Что проверяется сервером

Исходная строка `Telegram.WebApp.initData` передаётся заголовком на каждый финансовый запрос. Сервер проверяет HMAC-подпись, срок `auth_date`, ID из подписанного `user` и принадлежность к `MANAGER_IDS`. `initDataUnsafe` для доступа не используется, ID в теле запроса прав не даёт. В обычном браузере доступ к финансовым API закрыт. Бот-токен и ключ ЮKassa не передаются странице. При истечении авторизации закройте приложение и откройте его кнопкой заново.

При обрыве сети или тайм-ауте интерфейс сохраняет прежние показанные данные и выводит понятную ошибку. Неопределённость ответа не доказывает отсутствие операции: сервер мог сохранить её до обрыва. Обновите журнал; расход повторяйте с тем же ключом, пока страница остаётся открытой. Повторное подтверждение оплаты не добавляет второе поступление. Повторный полный возврат после завершения отклоняется.

В карточке заказа показывается ID платежа ЮKassa. Состояние «Оплачено» возникает только после подтверждения ЮKassa. Сводки используют даты подтверждений и целые копейки. Формулы и выбранный период показаны рядом с результатами.

## Автоматические проверки

```bat
python -m unittest discover -s tests -v
node tests/test_ui.cjs
```

При реализации прошли 23 Python-теста и 5 проверок JavaScript: авторизация каждого API, роль менеджера, просроченная/испорченная подпись, подмена суммы заказа, pending и canceled без поступления, повтор платежа, повтор возврата, расходы 0 и −1, откат при ошибке, сохранность после повторного открытия файла и понятные ошибки связи в UI. Тесты используют временные базы и подставленные ответы провайдера. Они не заменяют реальную оплату через ваш тестовый магазин и демонстрацию двух клиентов Telegram.

## Протокол демонстрации преподавателю

Выполните вручную и запишите полученный результат; этот список не означает, что реальные Telegram-клиенты уже были проверены автоматически.

1. Покупатель А оформляет новый заказ через ЮKassa. До оплаты pending, поступления нет.
2. Оплатить официальной тестовой картой. Проверить «Оплачено», ID платежа, одно поступление, уведомление менеджеру.
3. Повторить проверку оплаты — поступление одно. Отдельный отменённый платёж поступления не создаёт.
4. Менеджер открывает Mini App кнопкой из бота, записывает расход 100 ₽. Обе сводки уменьшаются на 100 ₽.
5. Запросить полный возврат. До подтверждения ЮKassa итог прежний; после подтверждения один refund в журнале. Повтор нового возврата отклоняется.
6. Покупатель Б не видит заказ А; прямой финансовый API с его initData получает 403.
7. Перезапустить через start-miniapp.cmd, открыть новую кнопку Mini App, сверить тот же период с ручным расчётом. Заказы и операции остаются в файле базы.

Отдельно продемонстрируйте расходы 0/−1, старую/неверную авторизацию и остановку сети. На скриншотах не показывайте `.env`, токены, секретный ключ, сырую initData или настоящие платёжные данные.

Документация: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [временные HTTPS-туннели Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).
