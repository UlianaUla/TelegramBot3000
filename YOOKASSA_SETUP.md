# Тестовая оплата через ЮKassa

Имитатор отключён в боте и финансовом API. Старые учебные платежи сохранены для просмотра; их кнопки больше не меняют статус. На экране оформления доступны ЮKassa и расчёт при получении. Локальный `.env` настроен на предоставленный вами тестовый магазин; его ID не записан в исходники или шаблон настроек.

## 1. Получите секретный ключ

В личном кабинете выберите нужный **тестовый** магазин и откройте **Интеграция → Ключи API**. Скопируйте секретный ключ тестового магазина. При необходимости выпустите ключ кнопкой в кабинете. Этот ключ и `BOT_TOKEN` остаются только на вашем компьютере.

На вашем скриншоте открыт соседний раздел **HTTP-уведомления**. В текущей реализации webhook не используется: бот сам запрашивает статус у ЮKassa каждые 15 секунд и по кнопке «Проверить оплату». Поэтому форму URL уведомлений сейчас можно закрыть кнопкой «Отменить», произвольный адрес в неё вводить не нужно. Адрес Mini App тоже не является webhook платежей. Для обычной оплаты по ссылке публичный сервер и HTTPS-туннель не требуются; они нужны отдельно для Mini App.

## 2. Заполните локальный `.env`

В cmd:

```bat
cd /d "C:\Users\User\Desktop\Telegram bot"
notepad .env
```

Строка `YOOKASSA_SHOP_ID` уже заполнена. Впишите ключ после `YOOKASSA_SECRET_KEY=`. Проверьте, что `YOOKASSA_RECEIPT_EMAIL` содержит учебную почту, например `foliant-study@example.com`. `PAYMENT_MODE=yookassa` уже установлен. Токен бота не меняйте. `PROVIDER_TOKEN` для этой интеграции не нужен: используется redirect-ссылка ЮKassa, а не Telegram invoice.

Не присылайте ключ в чат и не делайте скриншот `.env`. В `.env.example` только пустые значения ключей.

## 3. Перезапустите и оформите заказ

В окне работающего бота нажмите Ctrl+C, затем:

```bat
python -m bot
```

Если используете виртуальное окружение, запускайте `.venv\Scripts\python.exe -m bot`. В Telegram откройте `/start`, выберите книгу, корзину, оформление, имя и самовывоз. На экране проверки нажмите **«Оплатить через ЮKassa»**, затем **«Перейти к оплате»**. Кнопка **«Подтвердить заказ»** означает расчёт при получении, а не запуск ЮKassa.

Используйте новый заказ: старый заказ имитатора не переключается на другого провайдера. После перезапуска старые сообщения Telegram останутся, но учебные кнопки в них уже отключены.

На странице оплаты используйте только тестовые данные из документации: карта `5555 5555 5555 4444`, любая будущая дата (например 12/30), любые три цифры CVC. Для этой карты 3-D Secure не требуется. Настоящую карту не вводите. Реальные деньги в тестовом магазине не списываются.

Вернитесь в Telegram и нажмите **«Проверить оплату»**. При ответе ЮKassa `succeeded` появится «Оплачено» и одна операция поступления. Можно дождаться фоновой сверки. Проверьте ту же операцию в **Операции → Платежи** тестового магазина. Пока бот остановлен, автоматической сверки нет; она продолжится после запуска.

## Если оплата не началась

- «Онлайн-оплата не настроена» — проверьте ключ, ID, почту и перезапустите бота.
- Ошибка авторизации ЮKassa — ключ должен относиться к выбранному тестовому магазину; проверьте отсутствие лишних пробелов.
- Ошибка параметров чека (`receipt`) — сверяйте режим чеков тестового магазина с учебными настройками кода. Не отключайте чеки вслепую: текущий запрос передаёт чек с учебной почтой и НДС «без НДС».
- «Оплачено» не появилось — нажмите проверку и посмотрите статус операции в кабинете ЮKassa. Не подтверждайте получение денег вручную.

Инструкция согласована с официальными страницами [тестирования](https://yookassa.ru/developers/payment-acceptance/testing-and-going-live/testing) и [настройки тестового магазина](https://yookassa.ru/docs/support/merchant/payments/implement/test-store).
